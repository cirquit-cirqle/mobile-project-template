# 要件定義 インデックス

## 概要

本ディレクトリは、プロジェクトの要件定義を体系的に管理するためのテンプレート群です。
要件は以下の3カテゴリに分類し、各ドキュメントで詳細を定義します。

## ドキュメント構成

| # | ドキュメント | 内容 | 必須 |
|---|---|---|---|
| 01 | [機能要件](01_functional_requirements.md) | ユーザーストーリー、ユースケース、画面一覧、機能一覧 | Yes |
| 02 | [非機能要件](02_non_functional_requirements.md) | パフォーマンス、セキュリティ、アクセシビリティ、多言語対応等 | Yes |
| 03 | [制約条件](03_constraint_requirements.md) | 技術的制約、ビジネス制約、法的制約、運用制約 | Yes |

## 要件管理ルール

### ステータス定義

| ステータス | 意味 |
|---|---|
| Draft | 起票済み・レビュー前 |
| Review | レビュー中 |
| Approved | 承認済み |
| Deferred | 延期 |
| Rejected | 却下 |

### 優先度定義

| 優先度 | 意味 | 基準 |
|---|---|---|
| P0 - Critical | 必須 | リリースに不可欠。これがないとサービスが成立しない |
| P1 - High | 重要 | 初回リリースに含めるべき。ユーザー体験に大きく影響 |
| P2 - Medium | 中程度 | 次回以降のリリースで対応可。あると望ましい |
| P3 - Low | 低 | 余裕があれば対応。なくても大きな問題はない |

### 要件ID規則

```
[カテゴリ]-[連番3桁]

例:
  FR-001  ... 機能要件（Functional Requirement）
  NFR-001 ... 非機能要件（Non-Functional Requirement）
  CR-001  ... 制約条件（Constraint Requirement）
```

### 変更管理

要件の変更は以下のプロセスに従うこと:

1. 変更要求の起票（変更理由・影響範囲を明記）
2. ステークホルダーレビュー
3. 影響分析（仕様・テスト・実装への影響）
4. 承認 / 却下
5. 承認後、関連ドキュメントの更新

## 利用方法

1. 各テンプレートの `<!-- [PLACEHOLDER] -->` 部分をプロジェクト固有の内容に置換する
2. 不要なセクションは削除してよいが、削除理由をコメントで残す
3. 要件追加時は既存のID体系に従って採番する
