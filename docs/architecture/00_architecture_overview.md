## 3. 設計原則

本プロジェクトでは以下の設計原則に従う。

### 3.1 基本原則

| 原則 | 説明 | 適用場面 |
|---|---|---|
| **関心の分離** | UI・ビジネスロジック・データアクセスを明確に分離する | レイヤー設計全般 |
| **単一責任の原則** | 各クラス・関数は一つの責務のみを持つ | 全コンポーネント |
| **依存性逆転の原則** | 上位レイヤーは下位レイヤーの抽象に依存する | Service / Repository |
| **テスタビリティ** | 全てのビジネスロジックがユニットテスト可能であること | 設計判断全般 |
| **プラットフォーム非依存** | ビジネスロジックはプラットフォーム固有APIに直接依存しない | lib/services/, lib/models/ |

### 3.2 Flutterにおける設計方針

| 方針 | 説明 |
|---|---|
| **Widget は薄く保つ** | Widget にビジネスロジックを書かない。表示と操作の委譲のみ |
| **Immutable な状態管理** | 状態はイミュータブルなオブジェクトとして管理する |
| **Composition over Inheritance** | Widget の再利用は継承ではなくコンポジションで実現する |
| **const Widgetの活用** | 再ビルド不要なWidgetには `const` を付与しパフォーマンスを確保する |

## 4. 全体アーキテクチャ

### 4.1 レイヤー構成

```
┌─────────────────────────────────────────────┐
│              Presentation Layer              │
│  (Screens / Widgets / Providers)             │
├─────────────────────────────────────────────┤
│              Domain Layer                    │
│  (Models / Services / UseCases)              │
├─────────────────────────────────────────────┤
│              Data Layer                      │
│  (Repositories / DataSources / DTOs)         │
├─────────────────────────────────────────────┤
│              Infrastructure Layer            │
│  (HTTP Client / Local Storage / Platform)    │
└─────────────────────────────────────────────┘
```

### 4.2 依存方向

```
Presentation → Domain ← Data → Infrastructure
              (依存は内側に向かう)
```

- **Presentation** は Domain のみに依存する
- **Domain** は何にも依存しない（純粋なDart）
- **Data** は Domain の抽象（インターフェース）に依存する
- **Infrastructure** はフレームワーク・ライブラリに依存する

### 4.3 ディレクトリとレイヤーの対応

```
lib/
├── main.dart              # エントリーポイント、DI設定
├── screens/               # Presentation: 画面単位のWidget
├── widgets/               # Presentation: 再利用可能なUIコンポーネント
├── providers/             # Presentation: 状態管理（UIとDomainの橋渡し）
├── models/                # Domain: データモデル（エンティティ、値オブジェクト）
├── services/              # Domain: ビジネスロジック
└── utils/                 # 横断的ユーティリティ（フォーマッタ、定数、拡張）
```

## 6. クロスプラットフォーム戦略

### 6.1 コード共有方針

| 範囲 | 共有率目標 | 方針 |
|---|---|---|
| ビジネスロジック (Domain) | 100% | プラットフォーム非依存のDartコード |
| UI コンポーネント | 90%以上 | Material/Cupertino のAdaptive対応 |
| プラットフォーム固有処理 | 0% (個別実装) | Platform Channel / Federated Plugin |

### 6.2 プラットフォーム分岐方針

| 分岐パターン | 使用場面 | 実装方法 |
|---|---|---|
| Adaptive Widget | iOS/Android でのUI差異 | `Platform.isIOS` / `.adaptive` コンストラクタ |
| Platform Channel | ネイティブAPI呼び出し | MethodChannel / EventChannel |
| Conditional Import | Web固有の処理 | `dart:html` の条件付きインポート |
| kIsWeb | Web判定 | `foundation.kIsWeb` |

## 8. セキュリティアーキテクチャ

| 対象 | 方針 | 実装手段 |
|---|---|---|
| 通信 | 全通信TLS 1.2以上 | HTTPクライアント設定 |
| トークン保管 | セキュアストレージ使用 | flutter_secure_storage |
| 機密データ | メモリ上の保持時間を最小化 | 利用後の即時クリア |
| 入力値 | クライアント・サーバー両方でバリデーション | 共通バリデーションロジック |
| ログ | 個人情報・トークンのログ出力禁止 | ログフィルタリング |
