# CLAUDE.md ガイド

## 1. CLAUDE.md とは

`CLAUDE.md` は Claude Code がプロジェクトで作業する際に自動的に読み込む設定ファイルである。
コーディング規約・設計方針・プロジェクト固有のルールを記述することで、AIの振る舞いをプロジェクトに合わせて制御できる。

---

## 2. 配置場所と読み込み優先度

Claude Code は以下の場所にある `CLAUDE.md` を自動検出し、すべて読み込む。

| 場所 | スコープ | 用途 |
|---|---|---|
| `~/.claude/CLAUDE.md` | グローバル（全プロジェクト共通） | 個人の作業スタイル・汎用的な好み |
| `{プロジェクトルート}/CLAUDE.md` | プロジェクト全体 | プロジェクト固有のルール（本ファイル） |
| `{サブディレクトリ}/CLAUDE.md` | ディレクトリ以下 | 特定モジュールの追加ルール |

複数の `CLAUDE.md` が存在する場合、すべて読み込まれ内容はマージされる。
競合する設定はより具体的なスコープ（サブディレクトリ）が優先される。

---

## 3. このプロジェクトの CLAUDE.md 構成

本プロジェクトの `CLAUDE.md`（プロジェクトルート）は以下のセクションで構成されている。

| セクション | 内容 |
|---|---|
| 詳細コーディング規約へのリンク | `docs/architecture/06_coding_conventions.md` を参照させる |
| 命名規則 | クラス・変数・ファイル・bool型の命名パターン |
| コメントルール | `///`・`//`・TODO/FIXMEの使い分けと言語（日本語） |
| 設計原則 | 関数行数・引数・Widget制限・状態管理の置き場所 |
| AIスキル | `skills/` ディレクトリの各Skillへの参照テーブル |
| プロジェクト概要 | フレームワーク・アーキテクチャ・詳細ドキュメントへの誘導 |

## 4. CLAUDE.md の書き方

### 4.1 効果的な記述のポイント

**具体的なルールを書く**

```markdown
# 悪い例
コードをきれいに書くこと。

# 良い例
- 1関数は 30行以内。超える場合はプライベート関数に分割する
- 引数が3個を超える場合は名前付き引数を使う
```

**理由も添えると理解が深まる**

```markdown
# テストでデータベースをモックしない
# Why: モック/本番の乖離が過去にマイグレーション障害を引き起こした
```

**他のドキュメントへの参照を活用する**

```markdown
**詳細なコーディング規約:** [docs/architecture/06_coding_conventions.md](docs/architecture/06_coding_conventions.md)
```

CLAUDE.md を簡潔に保ち、詳細は別ドキュメントへ委ねることで可読性を維持できる。

### 4.2 記述すべき内容

- プロジェクト固有の命名規則・コーディングスタイル
- 禁止事項・注意事項（過去のトラブルから学んだこと）
- よく使うコマンドや開発フロー
- 重要なドキュメントへのリンク

### 4.3 記述しなくてよい内容

- コードから読み取れるアーキテクチャ・ファイル構成
- git履歴で確認できる変更経緯
- すでに他ドキュメントに書かれている内容（リンクで代用する）

---

## 5. サブディレクトリ用 CLAUDE.md の活用例

特定モジュールに追加ルールが必要な場合、そのディレクトリに `CLAUDE.md` を置く。

```
lib/
├── CLAUDE.md          # ← "このディレクトリのファイルは必ず Riverpod Provider に従うこと"
├── screens/
│   └── CLAUDE.md      # ← "Screen は StatelessWidget のみ使用すること"
```

---

## 6. CLAUDE.md のバージョン管理

`CLAUDE.md` はコードと同様に git で管理する。
チームで使用する場合はレビュープロセスを経てルールを追加・変更することを推奨する。

個人設定（グローバルの `~/.claude/CLAUDE.md`）はリポジトリに含めない。
